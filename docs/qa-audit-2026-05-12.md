## 2. P0 Findings (Block GA)

### P0-1. `pushWorkspace` has no rollback on partial failure

**File:** `packages/ui-components/src/store/workspaceStore.ts:3471-3556`
**Verified:** Yes — read in full.
The 6-step push (`getRef → getCommit → createBlob×N → createTree → createCommit → updateRef`) is unguarded. A pre-push snapshot is captured at line 3483, but it is never restored when an intermediate API call fails. Local `lastPushedSha` / `lastPulledSnapshot` mutation happens only after `updateRef` succeeds, so the _store_ won't corrupt on mid-flight failure — **however** orphaned blobs and the new commit (created on lines 3502, 3519) remain on GitHub regardless of success, accumulating with every retry.
**Repro:** Drop the network between `createCommit` and `updateRef`. New commit lingers on remote with no ref pointing at it; user retries, second push creates _another_ dangling commit.
**Fix:** Wrap the orchestration in `try/catch`; on catch, leave local state untouched (already correct) but surface the actionable distinction _"commit exists on remote but ref was not updated — your push partially succeeded; refresh to compare"_. Optional: GC orphan commits is a GitHub-side concern.

### P0-2. Diverged branch (force-push) yields a raw 422 instead of a clear "branch has diverged" UX

**File:** `workspaceStore.ts:3491-3528`
**Verified:** No pre-flight check that `branch.headSha === remote.headSha` _before_ uploading blobs.
**Repro:** Force-push from CLI, then push from Studio → `updateRef` fails with "References do not match expected SHA" surfaced as `GitHubError(422)`.
**Fix:** Read `getRef` once at the top; if `remote.sha !== branch.headSha`, throw `BranchDivergedError` with action `"Refresh first"` (the refresh modal already exists).

### P0-3. `refreshWorkspace` 3-way merge has no merge-base ancestry check

**File:** `workspaceStore.ts:4640-4687`
**Verified:** Yes — the diff is computed against `local.sync.lastPulledSnapshot` regardless of whether the remote SHA is a descendant of `lastPulledSha`. If `main` is force-pushed to an unrelated history, the diff still proceeds and `applyMerge` can silently re-apply local edits on top of an upstream that intentionally deleted them.
**Repro:** On GitHub, force-push `main` so `workspace.json` is wholly rewritten. Pull → merge "succeeds" → local copy now contains content the new upstream history never had.
**Fix:** Before computing the diff, call `getCommit` for `file.sha` and confirm it is reachable from `lastPulledSha` (walk parents up to a cap, or use `compareCommits`). If not, surface "Remote history was rewritten — open the snapshot diff before merging" and require explicit confirmation.

### P0-4. Network 15 s timeout in GitHub client is opaque to the user

**File:** `packages/git/src/github/api.ts` (timeout enforcement); UI handler at `WorkspacePanel.tsx:1136-1144`
The classify-error path returns `GitHubError(0)` with a string message. UI shows "GitHub API call failed" with no hint that a retry is reasonable. This compounds with P0-1: a user sees "Push failed" and retries without realising the commit object already landed remotely.
**Fix:** `classifyError()` should return a discriminated `TimeoutError`; UI should render _"Connection timed out. Your push may have partially landed — refresh first."_

### P0-5. `apps/e2e-mock` fails `tsc --noEmit`

**File:** `apps/e2e-mock/src/routes/status.ts:20`

```ts
return c.json({ status: code }, { status: code });
```

Hono's `c.json(body, statusOrInit, headers?)` second arg is `ContentfulStatusCode | ResponseOrInit`, not `{ status }`. Same mistake at line 14 (`{ error: 'invalid_status', got }`, `{ status: 400 }`) — typecheck only reports the line 20 hit because compilation halts there.
**Repro:** `pnpm check` → ELIFECYCLE exit 2 on `@apicircle/e2e-mock#check`.
**Fix:** Change `{ status: code }` second arg to `code as ContentfulStatusCode` and same for line 14.

## 4. P2 Findings (Usability / Edge Cases) — Highlights

Full agent reports retained in `docs/qa-audit-2026-05-12-appendix/` (see §7). Top themes:

**Empty / loading / error states**

- Response viewer renders the literal string `(empty body)` inside Monaco for an empty response. Render as a card outside the editor.
- MCP card on web is blank with no "(desktop required)" hint.
- After successful push, the green "Pushed abc1234" message stays on-screen forever — make it a toast.
- Attachment sync's `{ fetched, alreadyPresent, failed }` return is never displayed; users see no retry path for individual failed blobs.

**Validation lenience**

- Negative timeouts accepted for request and plan timeout fields.
- Plan name accepts unlimited length (renders broken in the sidebar beyond ~80 chars).
- Duplicate environment names, duplicate header names, duplicate context variables are all permitted.
- Assertion `matches` (regex) does not compile-test the regex at edit time.
- Multiplier `min > max` is accepted; runtime silently clamps to `min`.
- Validation rules: invalid regex / invalid JSON-Path silently always-false; user thinks rule logic is wrong, but it's their syntax.

**CORS defaults**

- `mcpServer.tools.mocks` creates mocks with `cors: { enabled: true, origins: ['*'] }`; UI creates them with `enabled: false`. Two paths, two defaults. Standardise to `enabled: false, origins: []`.
- Enabling CORS with empty origins applies `*` at the Hono layer (`mock-server-core/src/cors.ts:12`) — directly contradicts the panel copy "Off by default — same-origin only". Require ≥1 explicit origin before enabling.

**Race conditions**

- Port collision pre-flight check in `MockServersPanel.tsx:94-106` is TOCTOU; remove and rely on the runtime's own collision rejection.
- `portFinder.getFreePort` closes the listener before returning (`runtime/portFinder.ts:9-24`) — documented race; acceptable for single-user desktop but flag for hosted.

**Copy clarity**

- "Withdraw" vs "Yank" terminology is inconsistent across release UI.
- "Pull first" banner styles "Pull" as primary and "Skip" as secondary — implies pulling is required when it's optional.
- Rate-limit error shows ISO timestamp ("Resets at 2026-05-12T18:45:30.000Z") instead of "Resets in 17 minutes".
- "Create a working branch before pushing" error lacks an action verb pointing at the Workspace panel.

**Cross-editor consistency**

- Three different verbs for the same action: "Add row" / "Add variable" / "Add header" / "Add step" — pick one pattern.
- Destructive deletes have a `ConfirmDialog` in the Execution Plan and Release flows, but not in Headers / Env / Context. Either confirm everywhere or rely on undo everywhere.
- Escape closes some modals but not `SecretKeyPicker`.

## 7. Risk Heat-map (recommended fix order)

1. **Ship blockers** — fix P0-1 through P0-5 _before_ opening the gates. Three of the five are mechanical (`expectedHeadSha` pre-flight, merge-base check, Hono type fix); one is a UX layer over an existing error (timeout classify); one is the rollback semantics in `pushWorkspace`.
2. **Auth & destructive-action confirms** (P1-1, P1-2, P1-5, plus the missing P2 confirms in Headers/Env/Context) — single sprint; high signal/effort ratio.
3. **Linked workspaces clean-up** (P1-18, P1-19, P1-20) — these accumulate silent zombie data with use; fix before more workspaces are linked.
4. **Auto-update wiring** (P1-25) — without it, every released bug becomes permanent for installed users. `electron-updater` + a GitHub Release publish target is roughly half a day.
5. **Validation hardening** (the P2 lenience batch) — wire the existing `shared/validators.ts` helpers into every field that bypasses them today.
6. **Copy / consistency pass** (P2 + P3) — one designer-led review of every visible string.

## 8. What this audit did NOT cover

- **Manual UI exploration** with a running browser — this audit is source-only. Running `pnpm dev:web` and exercising flows by hand would surface additional layout/interaction issues a code read cannot catch (focus traps, scroll containment, paint flicker, text overflow on real content).
- **Cross-platform desktop builds** — only the build config and main-process source were inspected.
- **Security review** at the secrets / crypto layer beyond surface scan — `packages/core/src/auth/*` is well-tested per memory; a dedicated `/security-review` pass would be a sensible follow-up.
- **Performance under load** — no benchmarking of large workspaces (1k+ requests), large attachment sets, or sustained mock-server traffic.
- **Accessibility deep-dive** — axe is configured per project memory; an interactive screen-reader walk-through is the next step.
