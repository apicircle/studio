## What 'covered' means

- **Strict mode** (`--strict`, CI default): a TC-ID is counted only when a spec explicitly tags it with `tc('TC-XX-NNNN', ...)`, `tcCovered('TC-XX-NNNN')`, or `tcRange('TC-XX', from, to, ...)`. This is the honest "real test code references this row" number.
- **Lenient mode** (legacy default): also credits TC-IDs that appear in any `tcMap*.ts` file imported by the spec. Useful for tracking which modules are _wired_ to automation, but inflates the number — a spec that imports a 547-entry map gets credit for all 547 even if it only writes a handful of `test()` bodies.
- **Manual-residue tier** (`apps/web/e2e/manual-residue.ts`): TC-IDs explicitly excluded from automation — cross-OS installer signing, real-IdP live tier, perception perf, browser-chrome surfaces. These do not count against the gap; they're tracked separately and verified manually.

**Always use `--strict` when answering 'is this row really tested?'.**
